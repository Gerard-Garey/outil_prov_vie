# Conventions de la documentation de fond

Ces conventions s'appliquent au document unique de la documentation de fond, `docs/latex/doc_outil_prov_vie.tex` (`docs/exigences.md`, E3.1 à E3.4). Le vocabulaire est celui de `CONTEXT.md`. Le rédacteur est `docwriter` (`CLAUDE.md`, règle 9).

## 1. Charte et compilation

- Le document part de la charte `docs/latex/charte_graphique.tex` : le **préambule est repris sans modification**, hors du seul bloc adaptable de la charte, borné par `% >>> À ADAPTER : métadonnées du document (page de garde, pied de page, PDF)` et `% <<< À ADAPTER` ; le corps d'exemple de la charte est remplacé par le contenu (ADR 0003 annoté). La comparaison du préambule avec celui de la charte est faite par le script de contrôle `tests/controles/preambule_latex.R` (issue #8 ; ADR 0010, point 26), exécuté par la batterie unitaire et par le job « Documents LaTeX » de la CI.
- Valeurs du bloc adaptable : `\datedoc` est une **date figée**, jamais `\today` ; `\statutdoc` vaut `Projet` ou `Final` ; `\titredoc` (pied de page) et `pdftitle` portent le titre court ; `\datedroit` vaut `Sans objet` tant que le document ne cite aucun texte qui fait foi.
- On emploie les macros et environnements de la charte plutôt qu'une mise en forme ad hoc : `\partie`, `\section`, `\subsection`, `encadre`, `\reglement`, `\refl`, `fiche` (rubriques de la fiche méthode, `\Principe` à `\Referentiels` ; de la fiche modèle, `\Cadre` à `\LimitesModele`), `figureH`, `tableH`, `\code`, `\fsp`.
- **Compilation** : pdfLaTeX, trois passes, `-interaction=nonstopmode -halt-on-error`, hors du dépôt (les fichiers auxiliaires ne se versionnent pas). Attendus : code de sortie 0 aux trois passes, aucune ligne commençant par `! `, aucune référence indéfinie, aucun `Overfull`. Avertissements admis : `\headheight is too small` de `fancyhdr` (un par page, hérité de la charte, ADR 0003) et `statuts_sources.tex introuvable` (macro `\src` de la charte, inactive dans ce dépôt, voir § 5).

## 2. Plan du document

Ordre fixe, une partie (`\partie`) par bloc :

1. page de garde, page « Objet du document » (bandeau seul), sommaire ;
2. **Partie I, Présentation** : sections « Périmètre » et « Conventions » ;
3. **Partie II, Architecture** : sections « Package et point d'entrée » et « Quinze modules et leur graphe » (tableau des quinze modules, de leur rôle et des modules que chacun peut appeler, d'après l'ADR 0010, point 1) ;
4. **une partie par module**, dans l'ordre du tableau de l'ADR 0010, point 1 : `outils`, `dictionnaire`, `lecture`, `donnees`, `tables`, `garanties`, `engagement`, `triangle`, `risque_en_cours`, `regles_comptables`, `projection`, `plan`, `rapport`, `simulation`, `calculer_provisions` ; chacune ouvre par la section « Rôle et fonctions du module `<module>` » (rôle, modules qu'il peut appeler, tableau de fonctions), suivie des sections propres au module (fiches de méthode, catalogues) ; la partie `calculer_provisions` a en plus la section « Table des étapes » ;
5. **Partie « Tests »** : batteries (avec l'intégration continue), scripts de contrôle du dépôt (`tests/controles/`), références de non-régression (ADR 0011), harnais, concordance entre la documentation et le code.

Les éléments d'E3.1 encore absents (partie « cadre par référentiel et par garantie », fiches de méthode, index et traçabilité, bibliographie) s'ajoutent à leur place quand leur contenu existe. `\partie` n'a pas de compteur : un renvoi se fait par `\ref` vers l'étiquette d'une section (`sec:<nom>`), jamais par un numéro de partie écrit à la main.

## 3. Convention de concordance

La batterie `tests/concordance_doc_moteur.R` (en-tête du script : il fait foi) lit les tableaux de fonctions et les tableaux de constantes du document et les compare au code. Elle lit le **source** ligne par ligne, d'où ces règles, d'abord pour les tableaux de fonctions, puis pour les tableaux de constantes (issue #37) :

- **Marqueur.** Un tableau de fonctions est précédé d'une ligne de commentaire LaTeX seule sur sa ligne :

  ```
  % concordance-fonctions : <module>
  ```

  où `<module>` est l'un des quinze noms de l'ADR 0010, point 1 (écrit tel quel, `_` compris). Toutes les lignes qui suivent le marqueur sont lues, jusqu'à la première ligne qui contient `\end{tabular}`, `\end{longtable}` ou `\end{tabularx}` : le marqueur se place **juste avant** `\begin{tabular}`, sans texte entre les deux. Aucune autre ligne du document ne commence par `% concordance-fonctions`.
- **Première cellule.** Chaque ligne du tableau cite sa fonction dans sa première cellule par `\code{nom()}` ou `\code{nom}` (les `\_` sont acceptés). La première cellule est ce qui précède le premier `&` non échappé de la **ligne du source** ; tout `\code{…}` qu'elle contient est lu comme un nom de fonction. D'où : **une ligne de tableau par ligne du source** (une ligne coupée ferait lire comme fonction un `\code` d'une autre colonne), aucun `\code` dans la ligne d'en-tête ni dans la ligne « Aucune fonction. », aucune signature dans la première cellule (`\code{refuser()}`, jamais `\code{refuser(message, motif)}` : les arguments vont dans la colonne « Arguments »).
- **Un tableau par module**, jamais deux. Un module sans fonction garde son marqueur et un tableau à une seule ligne, `\multicolumn{3}{@{}l@{}}{Aucune fonction.}` : la batterie rend alors « 0 fonction(s) concordante(s) », et le tableau est prêt quand le module reçoit du code.
- **Fonctions recensées** : les fonctions de premier niveau de `R/<module>.R` dont le nom ne commence pas par un point (les auxiliaires à point ne sont pas citées) ; les constantes ne sont pas des fonctions. Chaque `export()` du `NAMESPACE` doit figurer dans un tableau.
- **Écarts relevés** : fonction du code absente du tableau, fonction citée absente du code, fonction citée deux fois, deux tableaux pour un module, module inconnu, module qui a des fonctions sans tableau, fichier de `R/` hors des quinze modules, export non cité. Avec `--strict` (CI), tout écart et l'absence du document font échouer la batterie ; sans `--strict`, les écarts sont des `[AVERT]` et le statut de sortie vaut 0.
- **Forme du tableau de fonctions** (la même pour les quinze modules, à six exceptions près) : trois colonnes, « Fonction » (`p{3.9cm}`), « Arguments » (`>{\raggedright\arraybackslash}p{3.0cm}`, « Aucun » s'il n'y en a pas), « Rôle » (`p{8.2cm}`, une phrase courte et juste, écrite d'après le code) ; exceptions : les tableaux des modules `dictionnaire`, `donnees`, `engagement`, `risque_en_cours`, `rapport` et `calculer_provisions` ont les largeurs `p{5.6cm}`, `p{3.0cm}` et `p{6.5cm}`, pour que leurs noms de fonction les plus longs (`\code{controler\_version\_extraction()}`, `\code{garanties\_couverture\_exclue()}`, `\code{valeur\_actuelle\_probable()}`, `\code{calculer\_risque\_en\_cours()}`, `\code{representation\_resultat()}`, `\code{format.resultat\_provie()}`) tiennent dans leur cellule sans dépassement (*Overfull*) ; une coupure dans le `\code{…}` de la première cellule n'est pas admise, la batterie y lit le nom ; en-tête `\rowcolor{tableheader}` en gras bleu, lignes alternées `\rowcolors{2}{tablerow}{white}`, dans un `center` en `\small` ; un tableau trop long pour une page (*Overfull* vertical) est un `longtable` en `\small`, même en-tête répété par `\endfirsthead` et `\endhead`, le marqueur juste avant `\begin{longtable}` (cas du module `donnees`).
- **Tableau de constantes.** Un tableau de constantes est un tableau dont la première cellule de l'en-tête contient `\textbf{Constante}` ; il appartient au module du dernier marqueur `% concordance-fonctions` qui le précède (un tableau de constantes placé avant tout marqueur est un écart). On le place donc dans la partie de son module, après le tableau de fonctions. Chaque rangée cite **une** constante, seule dans sa première cellule, par `\code{NOM}` ; seules les constantes de premier niveau de `R/<module>.R` dont le nom est en majuscules (`^[A-Z][A-Z0-9_]*$`) sont lues : les constantes internes à point (`.RANGS_CAUSES`) ne vont pas dans un tableau de constantes (citée dans un tableau, une telle constante est un écart, « absente » du module). La batterie évalue chaque constante sans charger le package (affectations de premier niveau des fichiers de `R/`, modules dans l'ordre de l'ADR 0010, point 1).
- **Complétude** (issue #41, décision du mainteneur du 12 novembre 2026, M408). Le tableau de constantes d'un module recense **toutes** ses constantes : chaque constante de premier niveau de `R/<module>.R` au nom en majuscules (affectation `<-`, `=` ou `->` à un nom, dont la valeur n'est pas une fonction ; `<<-` et `:=` ne sont pas recensés) y a sa rangée. Une constante absente du tableau est un écart, et un module qui a de telles constantes sans tableau de constantes en est un aussi, comme pour les fonctions. Un module qui reçoit sa première constante reçoit donc son tableau de constantes, dans sa partie, après le tableau de fonctions.
- **Valeurs littérales comparées.** La valeur se lit dans la deuxième cellule et, pour un tableau à trois colonnes, dans la troisième ; quatre formes sont comparées à la constante, toute autre rédaction n'étant pas lue :
  - **chaîne** : la deuxième cellule commence par `\code{"texte"}`, comparé à une constante chaîne de longueur un ;
  - **entier** : la deuxième cellule commence par « entier `\code{N}` » (ou « Entier »), comparé à une constante de type `integer` de longueur un (`1L`, non `1`) ;
  - **décompte** : « <nombre> motifs », « chaînes », « lignes » ou « CSV », hors de tout `\code{}`, dans la deuxième ou la troisième cellule, le nombre en chiffres ou en lettres de « un » (ou « une ») à « vingt » (« dix-neuf motifs », « quatorze lignes ») ; comparé à la longueur de la constante, ou à son nombre de lignes pour un `data.frame`. **Un nombre composé en lettres au-delà de vingt** (« vingt-deux lignes ») n'est pas lu et constitue un écart : l'écrire en chiffres ;
  - **liste de valeurs** : suite de `\code{valeur}` séparés par « , » (virgule et espace), **sans guillemets**, au début de la deuxième cellule ou juste après un « `~:` » (deuxième ou troisième cellule) ; comparée à la constante, vecteur atomique, valeur par valeur et dans l'ordre. Un `\code{…}` seul en tête de la deuxième cellule est lu comme une liste d'une valeur.
- **Guillemets** (décision du mainteneur du 9 novembre 2026, M207). Tout `\code{"..."}` d'une deuxième ou troisième cellule qu'aucune forme n'a consommé est un écart, où qu'il se trouve : seule la forme « chaîne » en consomme un, en tête de la deuxième cellule. Sont donc des écarts « version `\code{"1.3"}` », une chaîne en troisième cellule et une liste écrite avec guillemets. Une cellule sans `\code{"..."}` dont aucune forme n'est reconnue reste non lue, sans écart : la batterie nomme alors la constante « sans valeur littérale lue ».
- **Rangées.** Une rangée de tableau de constantes peut tenir sur plusieurs lignes du source : elle est lue du « `&` » de sa première ligne jusqu'au « `\\` » final, qui peut être suivi de « `[…]` » et de filets (`\hline`, `\midrule`, `\toprule`, `\bottomrule`). Une rangée sans « `\\` » final avant la fin du tableau, et une rangée qui a plus de cellules que l'en-tête (deux rangées fusionnées par un « `\\` » manquant), sont des écarts.
- **Écarts relevés (constantes)** : valeur différente de celle du code, constante citée absente du module ou non évaluable sans le package, constante citée deux fois, tableau de constantes avant tout marqueur, première cellule qui n'est pas un `\code{NOM}` seul, constante du module absente de son tableau, module qui a des constantes sans tableau de constantes, décompte composé en lettres, `\code{"..."}` non consommé, rangée sans « `\\` » final, rangée plus large que l'en-tête. Avec `--strict`, comme pour les fonctions, ils font échouer la batterie ; sans écart, la batterie rend par module « constantes du module <module> : N citée(s), M valeur(s) littérale(s) concordante(s) », suivi des constantes sans valeur littérale lue.
- **Table des étapes.** La section « Table des étapes » de la partie `calculer_provisions` reproduit le tableau constant `ETAPES` (colonnes `etape`, `module`, `fonction`, `condition` ; ADR 0010, point 4). Elle ne porte pas encore de marqueur : la batterie ne lit pas encore `ETAPES`, et la convention de lecture se fixera avec elle.

## 4. Rédaction

- Lecteur : un relecteur externe, sans accès au code. Phrases courtes ; tout raisonnement qui fonde une décision figure dans le document.
- Vocabulaire de `CONTEXT.md`, tel quel ; un sigle s'écrit en entier à sa première occurrence, puis en sigle.
- Noms du code (fonctions, modules, colonnes, fichiers) en `\code{…}` dans le texte et les tableaux ; dans les titres de partie et de section, le nom d'un module s'écrit en romain (`Module risque\_en\_cours`).
- Les cinq statuts épistémiques ne se confondent jamais : résultat exact, résultat asymptotique, approximation numérique, constat de simulation, jugement d'expert.
- **Aucun chiffre issu d'une exécution** (E3.4) : les résultats sont dans le rapport figé et la fiche de calcul. Une constante du code se cite d'après le code ; tout autre chiffre se mesure, commande et sortie citées dans le compte rendu.
- Le document décrit ce que fait le code ; un module sans code le dit (« Ce module n'a pas encore de fonction. »).
- Aucune référence fabriquée ; un fait de `docs/recherche/` au statut « incertain » ou « non trouvé » ne se cite pas.
- Typographie : `~:` avant le deux-points, `\fsp;`, `\fsp!`, `\fsp?` ; guillemets `«~…~»` ; pas de tiret cadratin dans le texte ; aucune cellule de tableau vide (« Aucun », « Sans objet ») ; `-{}-` pour un double tiret dans `\code` (`-{}-strict`).

## 5. Points tranchés

- **Citation des textes qui font foi** (tranché, M110). Un texte se cite **en clair** (« Code des assurances, art. R343-3 »), dans la phrase, dans `\refl` ou en titre de `\reglement`, sans `\src{ID}` : ce dépôt n'a pas de registre des sources, et `\src` n'y imprime rien. Le statut de vérification d'un texte se lit dans `docs/exigences.md` § 2.8 et dans le rapport de recherche (`docs/recherche/2026-11-07-cadre-provisionnement-vie.md`), auxquels le document renvoie. Un registre des sources éventuel ferait l'objet d'une issue.
- **PDF versionné** (tranché, M111). Aucun PDF de la documentation n'est versionné avant le jalon de livraison B11 ; la CI compile seulement (job « Documents LaTeX »). L'emplacement du PDF (E3.1) se tranche en B11.
